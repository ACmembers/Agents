# 原生状态图片桌宠设计

## 背景
当前项目的目标不是重做功能，而是把桌宠产品形态升级为原生桌面应用，同时保留现有主要能力：
- 桌面常驻
- LLM 对话
- 角色形象切换
- 设置与模型管理

用户的核心使用方式是：输入一个信号后，LLM 直接返回固定状态码，应用根据状态码迅速切换到对应图片。也就是说，这个产品的重点不是复杂动画，而是**状态驱动的角色呈现**。

## 目标
- 采用原生桌面技术栈
- 保留现有主要功能和交互语义
- 让 LLM 输出稳定、可校验的状态枚举
- 让角色图片切换足够快，且可扩展到多角色包
- 保持后续可继续接入语音、提醒、更多状态

## 结论
推荐方案是 **Qt Quick / QML + Rust 核心**。

原因：
- QML 更适合透明悬浮、图片切换、状态过渡和轻量交互
- Rust 负责协议、状态校验、配置、模型调用和调度
- 这条路线最贴近“原生桌面产品”，同时不强迫重做业务功能

## 备选方案

### 方案 A：Qt Quick / QML + Rust
**推荐。**

优点：
- 最适合桌宠壳层和图片状态切换
- UI 表现自然，后续可加轻微动效
- Rust 可把 LLM 返回值、状态机和资源管理做稳

缺点：
- 需要重建现有前端 UI
- 学习/维护成本高于继续用 Web 壳

### 方案 B：Qt Widgets + Rust
优点：
- 传统桌面控件成熟
- 工程结构简单

缺点：
- 不适合以图片和视觉状态为核心的桌宠
- 做透明悬浮、细腻反馈和后续动效会更别扭

### 方案 C：继续现有项目 + Rust 加速
优点：
- 迁移成本最低
- 保留现有前端资产

缺点：
- 仍不是原生桌面产品
- 结构上会继续依赖 Web 壳

## 设计原则
- **功能不变，外壳重做**：先把产品做成原生桌面形态，再慢慢补能力
- **LLM 输出枚举，不输出 UI 细节**：模型只负责“当前状态应该是什么”
- **状态机本地化**：状态是否切换、切到什么图、是否节流，都由本地决定
- **资源表驱动**：角色包提供状态到图片的映射，不把逻辑写死在代码里

## 体系结构

### 1. QML 展示层
负责：
- 透明悬浮窗
- 图片显示
- 简单过渡动画
- 点击、拖拽、双击等交互入口

不负责：
- LLM 调用
- 状态判定
- 配置读写
- 资源解析

### 2. Rust 核心层
负责：
- LLM 请求与响应解析
- 状态枚举校验
- 状态切换节流
- 配置和角色包管理
- 与系统能力交互

### 3. 角色资源层
每个角色包包含：
- 元数据
- 状态映射表
- 图片资源
- 可选的默认提示词、角色人格和状态优先级

## 状态模型

LLM 只返回固定枚举，例如：
- `idle`
- `greeting`
- `thinking`
- `happy`
- `sad`
- `surprised`
- `listening`
- `sleeping`

本地应用收到后执行：
1. 校验是否合法
2. 映射到当前角色包中的图片
3. 如果当前状态优先级更高，则拒绝覆盖
4. 如短时间重复触发，则按节流策略处理

## 数据流
1. 用户输入信号或触发事件
2. Rust 发送上下文给 LLM
3. LLM 返回状态枚举
4. Rust 校验并归一化状态
5. Rust 通知 QML 切换图片
6. QML 立即展示对应角色图

## 关键组件
- **LLM Adapter**：封装模型请求与返回解析
- **State Resolver**：把模型输出转成受控状态
- **Role Pack Loader**：加载角色包和状态映射
- **Window Shell**：负责透明悬浮窗与交互
- **Image Presenter**：按状态切图并播放轻量过渡

## 资源包格式
角色包建议支持：
- `manifest.json`
- `images/`
- `state_map`
- `priority_map`
- 可选 `prompt` / `personality`

示例语义：
- `happy` -> `images/happy.png`
- `thinking` -> `images/thinking.png`
- `idle` -> `images/idle.png`

## 非目标
- 暂不做复杂骨骼动画
- 暂不做 Live2D 级别角色驱动
- 暂不把所有现有 Web 细节原样迁移
- 暂不重构功能定义，只重构承载方式

## 验收标准
- 启动后能显示原生桌宠窗口
- LLM 返回固定状态后，能在本地快速切到对应图片
- 状态映射可通过角色包配置，不写死在代码里
- 主要功能保持：桌宠显示、对话、设置、角色管理

## 建议落地顺序
1. 原生窗口与图片展示壳
2. Rust 状态机和 LLM 接口
3. 角色包格式与加载器
4. 设置面板与基础配置
5. 现有功能迁移和补全
