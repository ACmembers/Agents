# 句子级流式 TTS 合成

**状态**：备选（未采用）
**决策时间**：阶段 5 开始前重新评估
**主方案**：等 LLM 完整回复后一次性合成语音
**切换成本**：中 — 需新增播放队列管理、SSE 流分句逻辑

## 方案描述

LLM 流式回复按标点分句 → 每句立即送入 TTS 合成 → 按顺序播放音频队列。

```
LLM SSE 流: "天气不错。| 阳光明媚。| 适合散步。"
           ↓ 分句
TTS 队列:  [synthesize(S1)]  [synthesize(S2)]  [synthesize(S3)]
           ↓ 顺序播放
音频:      🔊 句1 → 🔊 句2 → 🔊 句3
气泡:      逐字追加全文
```

## 对比

| | 主方案（等完整回复） | 此方案（流式合成） |
|---|---|---|
| 首音延迟 | 3-5 秒（LLM 完整生成 + TTS 合成） | 1-1.5 秒（第一句即可播放） |
| 实现复杂度 | 简单 | 需播放队列、分句策略、错序处理 |
| 用户体验 | 等一会儿才开始说话 | 马上开始说话，更自然 |
| 音质风险 | 低（一次合成） | 中（多段拼接可能有间隙） |

## 分句策略

- 中日文通用标点：`。！？!?…\n`
- 逗号 `，,` 不分句（太碎）
- 最短句子长度：5 个字符
- 合并过短句子直到够长

## 迁移路径

1. Rust 侧新增 `SentencePlayer` 结构体：持有 `VecDeque<AudioChunk>`
2. `send_stream()` 回调中按标点分句 → `SpeechEngine::synthesize()` → 入队
3. QML 侧 `MediaPlayer` 的 `onStopped` 信号触发播放下一个
4. 若某句 TTS 失败 → 跳过该句，继续下一句
5. 最后一句播完 → 清理 temp 文件
